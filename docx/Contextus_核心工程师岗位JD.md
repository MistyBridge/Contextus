# 核心工程师 JD — Contextus

> 2026-08-14 · 远程 / 全职或长期兼职 · 团队唯一空缺的核心开发岗位

## 一、关于 Contextus

Contextus 是一个面向 AI Agent 的「会话状态运行时」：用户与 AI Agent 的每一轮交互自动成为一个 git commit（代码 + 对话 + 审计日志的世界快照）；会话呈树形结构——任意历史节点可分支（多世界线并行）、可回溯、可双向追溯；一套版本化规则全局生效。

MVP（M0~M4）已全部完成：核心层 ~1500 行 TypeScript、6 个测试文件零失败、真实窗口验收通过。团队：创始人（方向）、前端工程师（已到位）、PM（JD 已出）。**核心工程师是唯一空缺——你接手的是一份小而完整、文档齐备的代码资产，而不是一个烂摊子。**

## 二、岗位定位

**你拥有核心层的所有权**：设计、实现、测试、实验、文档沉淀。这个岗位之前的全部产出都在这份资产的交接包中（见下），你从第一天起就能独立决策。

## 三、职责

1. **核心层设计与实现**（TypeScript / Node 22）：现有模块 twin（一轮生命周期/提交监控）、policy（规则双通道/条目 diff）、sessions、records、git 封装（含 cat-file 批量读）、claude（窗口唤起/无头执行）、store（独立模式）、TUI
2. **Phase 2 功能落地**（候选池已由创始人/PM 共识）：重建分支（压缩历史链上下文 → 新树 → 挂 skill/mcp 基础上下文之下）、scrub 历史清理、记忆目录版本化、完整 Chunk 体系与 Context Resolver、Context Merge、REST API 与多 Agent——按 PM 的方案文档逐个交付
3. **测试与验收协议维护**：九场景、七项硬指标、回放协议（REPLAY_N 可调）、升级回归（`upgrade-check.sh`，Claude Code 每次升级必跑——会话格式是非官方契约，这是唯一护栏）
4. **实验记录文化**：本项目最大的工程资产是**文档**——每个实测发现必须沉淀进 `docx/Contextus_架构与实验记录.md`（格式事实、陷阱清单、性能数据），让知识属于团队而不是某个人
5. **为前端工程师提供本地服务端**（server/ 层，Fastify 类）：把核心能力整理成 JSON API + SSE 实时事件——与前端共享类型，契约零重复

## 四、知识要求

| 要求 | 说明 |
|------|------|
| TypeScript / Node.js | 基础能力 |
| **git 深度（决定性）** | 不是「会用 git」，是懂数据模型：plumbing 级操作（rev-list / ls-tree / cat-file / update-ref / symbolic-ref / 索引与工作区分离）、分支图语义（DAG vs 单父树）、内容寻址与不可变对象——**这是产品的物理与语义基础** |
| Windows 11 实战 | 本项目一半的坑在平台层：路径编码（每个非字母数字字符 → `-`）、子进程与 .cmd 陷阱、终端窗口唤起、锁文件——**全部已解决并记录**，但新问题需要你有平台直觉 |
| Claude Code 会话格式 | 行为实验结论（格式非契约）——入职第一课就是读实验记录，但需要你有快速吸收并验证的能力 |
| Benchmark 驱动的测试文化 | 验收断言先于开发；零 API 测试优先（合成记录覆盖纯 git 层，真实 claude 轮次只测必要链路） |
| 代码文化 | 高内聚低耦合、最小依赖（当前仅 jsdiff）、控制代码膨胀——这是创始人的硬性要求 |
